# 🔴 ЧАСТЬ 1. Три бага в `03_TECH` §4.2 — исправить до первой строки геймплея

Это не стилистика. Каждый из трёх даёт тихий рассинхрон или враньё игроку. Все три уже исправлены в коде, который лежит в `packages/sim`.

## Баг 1. `fpMul` теряет точность молча

```ts
// 03_TECH §4.2 — НЕ РАБОТАЕТ
const fpMul = (a: Fixed, b: Fixed): Fixed => Math.round((a * b) / 65536) | 0;
```

`a` и `b` — int32. Их произведение доходит до **2⁶²**. Double точен только до **2⁵³**. Всё, что выше, округляется — молча, без ошибки, с результатом, зависящим от значений.

Проверка на конкретном примере:

| Выражение | Правильно | Даёт формула из спеки |
|---|---|---|
| `fpMul(-1, 65536)` | `-1` | `-1` ✓ (мелкие числа проходят) |
| `fpMul(2000000, 2000000)` | детерминированное значение | **потеря младших бит** |

Симптом в проде: бой сходится на десктопе и расходится на телефоне при больших статах — то есть **в позднем гейме, после релиза**.

**Рабочая реализация** (`packages/sim/src/fixed.ts`) — разбиение обоих операндов на hi/lo по 16 бит:

```ts
export function fxMul(a: Fx, b: Fx): Fx {
  const ah = a >> 16, al = a & 0xffff
  const bh = b >> 16, bl = b & 0xffff
  return ((Math.imul(ah, bh) << 16) + Math.imul(ah, bl) +
          Math.imul(al, bh) + ((al * bl) >>> 16)) | 0
}
```

Корректность последнего слагаемого: `al*bl ≤ 65535² = 4 294 836 225 < 2³²`, поэтому `>>> 16` не теряет старших бит.

Заодно отклонён и второй наивный вариант, `((a & 0xffff) * b) >> 16`: оператор `>>` делает ToInt32 **до** сдвига, старшие биты теряются раньше.

## Баг 2. `Rng` в спеке — не PCG32

```ts
// 03_TECH §4.2
class Rng {
  private state: number;                              // ← 32 бита
  constructor(seed: number) { this.state = seed >>> 0; }
}
```

PCG32 требует **64-битного состояния**. С 32 битами это уже не PCG, а обычный LCG: короткий период, плохие младшие биты, проваленный BigCrush. Для игры, где RNG определяет проки скиллов и выпадение из гачи, это заметно на дистанции.

**Реализовано и проверено:** hi/lo пара uint32, 64-битное умножение через четыре `Math.imul`, константы `6364136223846793005` / `1442695040888963407`.

**Совпадает с эталонными тест-векторами** референсной C-реализации (initstate=42, initseq=54):

```
a15c02b7 7b47f409 ba1d3330 83d2f293 bfa4784b cbed606e
```

Тест в `packages/sim/test/rng.test.ts` — зелёный. Это значит, что наш RNG бит-в-бит совместим с эталоном, и серверная валидация реплеев на любом языке сойдётся.

## Баг 3. `nextBelow` врёт игроку — прямое нарушение столпа 4

```ts
// 03_TECH §4.2
nextBelow(n: number): number { return this.next() % n; }
```

Это **modulo bias**. `2³²` не делится нацело на `n`, поэтому первые `2³² mod n` значений выпадают чаще остальных.

Столп 4 сформулирован как «Объявленные шансы = реальные шансы». `% n` делает это утверждение ложным — не грубо, но систематически и навсегда.

**Реализовано:** отбраковка смещения.

```ts
export function rngBelow(s: RngState, bound: number): number {
  if (bound <= 1) return 0
  const threshold = (4294967296 - bound) % bound
  for (;;) {
    const r = rngNextU32(s)
    if (r >= threshold) return r % bound
  }
}
```

Тест: 700 000 бросков в 7 корзин, отклонение каждой корзины < 1%. Зелёный.

## Плюс одно улучшение: таблица синуса

Спека предлагает `SIN_TABLE = new Int32Array(1024)` на полный оборот `[0, 2π)`.

Реализовано лучше при том же размере: **четверть волны, 1024 записи** (эквивалент полной таблицы на 4096) + углы как BAM (uint32, полный оборот = 2³²).

Три бесплатных свойства BAM:
1. Взятие по модулю 2π — естественное переполнение uint32, ноль кода
2. Range reduction точен по построению — а это самый коварный источник расхождений в трансцендентных функциях
3. Старшие биты — индекс таблицы, следующие — дробь для интерполяции

| | Спека | Реализовано |
|---|---|---|
| Ошибка интерполяции | ~2 LSB Q16.16 | **0.50 LSB** |
| Размер | 4096 байт | 4100 байт |
| Скорость | — | **в 3.2 раза быстрее `Math.sin`** (32.9 нс против 106.5) |

Отдельно: `fpSqrt` из спеки в симуляции **не нужен вообще**. Для выбора цели и проверки дальности сравниваются квадраты расстояний. Корень нужен только для нормализации вектора движения — там стоит `fxInvSqrt` с range reduction (без неё Ньютон расходится при x > ~500, это зафиксировано тестом).

# 🔴 ЧАСТЬ 2. Конфликты, требующие твоего решения

## Конфликт A. Сетка: 4×5=20 против 6×5=30 ⚠️ ломает бюджет 840

Ты ответил на мой вопрос «6 линий × 5 рангов = 30». Но твоя же спека говорит другое:

- `02_GDD` §3.3: «4 ряда × 5 колонок = **20 слотов, потолок**»
- `02_GDD` §4.3: `maxDeploy = 6 + floor(prestige/5)` → на престиже 70 ровно 20
- `01_RESEARCH` §3.1: «потолок 20»
- `01_RESEARCH` §3.3: полная таблица престижа, финальная строка «80+ → 20»

**И главное — откуда взялось число 840.** `01_RESEARCH` §3.4 дословно:

> «Максимум юнитов в бою: 20 героев × (1 + 20 миньонов) = **420 на сторону, 840 всего.** Это ключевое число для технической спеки.»

Если слотов 30, то `30 × 21 × 2 = 1260 юнитов`. Это **+50% к бюджету симуляции и рендера**, на который завязаны все перф-гейты: тик ≤ 4 мс, p99 ≤ 10 мс, 60 fps на iPhone SE 2020.

**Мой ресерч ничего этому не противоречит.** Цифры «5 рангов глубины» и «до 6 линий» я вытащил из **ремейка 2025**, а не из оригинала 2013. Твоя спека реконструирует оригинал, где 4 колонки глубины подтверждаются и китайским описанием («四排位置安排»), и разбором формаций.

**Рекомендую вернуться к 4×5=20.** Твоя цифра консистентна с тремя другими местами спеки и с бюджетом производительности. 30 слотов — это отдельное решение, которое тянет за собой пересчёт `maxDeploy`, бюджета юнитов и всех перф-гейтов.

Если всё-таки 30 — скажи, я пересчитаю бюджеты и перепишу перф-гейты. Но это решение уровня «переписать `03_TECH` §5», а не «поменять константу».

## Конфликт B. Ручные скиллы против `02_GDD` §9 ⚠️

Ты ответил «3–4 ручных скилла как в оригинале». Твоя спека, `02_GDD` §9 «Что НЕ входит в скоуп»:

> - ❌ Ручное управление в бою (нарушает столп №1)
> - ❌ **Активация скиллов игроком**

И `00_START_HERE` §2: «тактического авто-баттлера, где игрок **не управляет боем вообще**».

Разбор — почему у решения есть основания и чего оно стоит — в `DECISIONS.md` ADR-002. Коротко:

**За:** разработчики оригинала сами отказались от чистого автобоя через два года, добавив Morale Skills. Игроки высокого ранга строили вокруг них всю мету. Топ-1 претензия к оригиналу — «each battle seemed the same» — это претензия к пассивности.

**Против — четыре конкретные цены:**

1. **Скип и автобой становятся спорными.** `02_GDD` §7.1 требует «мгновенный автобой (пропуск с результатом)». Если касты нужны для победы, скип = проигрыш. → Обязательное ограничение: любой бой кампании проходится **без единого каста**, касты дают ~10–15% края.
2. **Реплей дорожает.** `03_TECH` §1 обещает «реплеи размером 200 байт: seed + две формации». С кастами реплей = seed + формации + **лог входов с номерами тиков**. Детерминизм не страдает, обещание «200 байт» — да.
3. **PvP становится асимметричным.** Атакующий кастует, сохранённая формация защитника — нет. Это ровно проблема оригинала.
4. **Онбординг +1 механика.** Вводить не раньше 4–5-го боя.

**Урок оригинала:** Morale Skills выпустили **без кулдаунов** и добавили их только патчем 2015-09 (Militia 7 с, Heal 13 с, Ninja 5 с, Bomb 3 с, Giant 7 с, Mist 20 с). Неограниченный каст ломал бой. Кулдауны закладываем сразу.

**Нужно от тебя:** новая редакция столпа 1 и вычеркнутая строка в §9. Предлагаю:

> **1. Формация — это геймплей.** Исход боя определяется подготовкой; ручные действия в бою дают **край**, а не победу. Ручного таргетинга нет.

## Конфликт C. Формула урона — вычитающая или процентная

Твоя спека честно помечает это как пробел. `01_RESEARCH` §5.2:

> «При ATK=2191 и крите урон ~900 → множитель ≈ 0.3–0.4»

и в списке нерешённого: «точная формула редукции урона защитой».

**Мой ресерч эту дыру закрыл.** Систематические замеры сообщества (июнь 2015, boxplot-отсев выбросов):

> «For every **10 defense**, critical damage taken is reduced by **4**»
> «Normal damage taken is reduced by **2**»
> «Every **2.5 defense** reduces **0.5** damage taken»

→ обычный урон снижается на **DEF / 5**.

**Три независимых подтверждения:**

| Проверка | Расчёт | Сходится |
|---|---|---|
| Прямое утверждение | 290 DEF → 58 урона | 290 × 0.2 = 58 ✓ |
| Сплэш Bomb Thrower | `2588 × 10% − (400 ÷ 5) = 178` | 258.8 − 80 = 178.8 ✓ |
| Отдельный замер | «70 def reduces 28 physical damage» | 70 × 0.4 = 28 (критовый коэффициент, ровно вдвое) ✓ |

Плюс: крит применяется **после** брони, и есть **пол урона** — минимум 10 обычным ударом, 20 критом.

```
Normal = max(10, Raw − DEF/5)
Crit   = max(20, (Raw − DEF/5) × 2)
```

**То есть оригинал был вычитающим, а твоя спека предлагает процентный `raw × K/(K+DEF)`.**

Это не «ты неправ» — это развилка:

| | Вычитающая (оригинал) | Процентная (твоя спека) |
|---|---|---|
| Историческая точность | ✅ подтверждена замерами | ❌ |
| Пороги неуязвимости | есть — нужен пол урона | нет |
| Читаемость контров | резче, жёстче | мягче, градиентнее |
| Масштабирование в поздний гейм | ломается, требует ручной подгонки K | чистое |
| Твоя цель «максимальная точность повторения» | попадает | не попадает |

Обе рабочие. Мой совет: **вычитающая**, раз цель — точность, и раз она даёт более читаемые контры (столп 2). Но процентная проще в балансе на длинной прогрессии до уровня 200.

## Конфликт D. Лейновая изоляция — её нет в спеке, а она была ядром тактики

`02_GDD` §3.5 задаёт таргетинг через взвешенный score с `W_dist`, `W_affinity`, `W_counter`, `W_hero`, `W_lowhp`. Это «суп»: все дерутся со всеми по весам, структуры поля нет.

**В оригинале лейны были почти изолированы.** Дословно из систематического разбора:

> «Each lane is rather 'independent' to each other as everyone kills the enemy in same lane before helping other lanes»
> «inter-lane fighting only happens in 2 conditions: 1. Enemies in same lane are all dead 2. Archers and mages can attack **across** lane»

Различие по классам подтверждено отдельно:
> «Mages and archers target closest targets within their CIRCULAR range, unlike other minions that search for targets **in the same row**»

**Почему это важно, а не деталь.** Изоляция лейнов делает **пустую клетку тактическим инструментом**. Мета-формация «Top Shield» — верхние 2 ряда намеренно пустые, чтобы вражеская кавалерия бежала через всё поле к пикинёру в глубине:

> «The key of this formation is that you decide how enemy act **without using any Morale Skills**»

В score-модели из `02_GDD` пустой лейн не делает **ничего**. Ты теряешь целый пласт решений — тот самый, который делал «формацию геймплеем».

**Рекомендация:** добавить лейновую структуру поверх score-модели. Это не замена, а ограничитель: melee ищет цель в своём ряду, `W_dist` работает внутри ряда; ranged (Archer, Arbalist, Mage) стреляют по кругу через ряды; выход из ряда — только когда ряд зачищен. Кавалерия с её пониженным `W_dist` остаётся исключением, которое и делает её кавалерией.

**Про рост статов 0.08 против 0.05.** На уровне 200 разница огромная: `×16.9` против `×10.95`. Твоя формула делает уровень заметно более сильной осью прокачки. Возможно, намеренно (тогда стоит записать почему), возможно — рассинхрон.

**Про pity 60 при базовом шансе 4★ = 2%.** Матожидание до 4★ при 2% — **50 роллов**. Pity на 60 срабатывает реже, чем «естественное» выпадение, то есть почти не связывает. Ремейк 2025 использует 30. Если pity задуман как настоящая страховка от невезения — он должен быть заметно ниже матожидания, иначе это украшение.

# 🟢 ЧАСТЬ 3. Что мой ресерч добавляет к твоему

Вынесено в `01a_RESEARCH_ADDENDUM.md`. Коротко — чего в твоём `01_RESEARCH` нет:

1. **Формула редукции урона защитой** — у тебя помечена как нерешённая, у меня закрыта тремя сходящимися замерами (Конфликт C).
2. **Правило лейновой изоляции** с дословными формулировками и различием melee/ranged (Конфликт D).
3. **Приоритет таргетинга при равных дистанциях — вниз.** Тесты: «AI goes down before up». ⚠️ Это геометрический приоритет; наш обход по возрастанию `entityId` обязан быть тай-брейкером **поверх** него, иначе равные дистанции недетерминированы.
4. **Кап целей AoE = 15** (патчноут v1.9).
5. **Мультипликативный стек баффов**: +36% и −36% дают −13%, не 0% (1.36 × 0.64 = 0.87).
6. **Пол урона**: 10 обычным, 20 критом.
7. **Подтверждение твоего `SKILL_BUDGET` вторым независимым способом.** У шести 4★-героев произведение `procChance × skillDamage` держится в коридоре **380–415, разброс ±4.5%**. Дизайнеры оригинала считали ровно твой инвариант. Отдельно: кривая `× (1 + 0.05 × lvl)` подтверждена **точно** на ремейке — отношение прироста к базе равно 0.05 на шести героях по всем пяти статам.
8. **Числовая матрица контров ремейка 2025** — единственная опубликованная в числах. Три свойства, которые стоит унаследовать: асимметрия (есть штрафы −15%/−20%, а не только бонусы), разрежённость (маги и жрецы без преимуществ), **один экстремум** (Archer→Pegasus +120% при остальных 20–40%). Твоя матрица в `02_GDD` §3.2 плотная, симметричная по духу и без экстремумов — читаемость от одного жёсткого контра выше.
9. **Реестр 12 пунктов, которых нет ни в одном открытом источнике** — базовые статы юнитов, формула Luck, формула Dodge, числа дальностей и скоростей, таблицы экипировки. Проектируем с нуля, знаем об этом заранее.
10. **Зафиксированная галлюцинация.** Цифра «7 рядов × 4 колонки» ходит по ресерч-выдаче, но на странице-источнике её нет — модель достроила её из читательского комментария «If there are 7 rows (I think there are...)». Дважды. Не использовать.
