## Как читать

Каждая задача = **вход → выход → инварианты → тесты**. Тесты пишутся **до** реализации.

**Префиксы ID** соответствуют пакетам:
`SIM` — ядро симуляции (zero dependencies) · `DATA` — контент и схемы · `RENDER` — PixiJS · `META` — прогрессия и сейв · `APP` — оболочка и экраны · `TOOLS` — тулинг, бенчи, балансировка · `P0` — организационные

**Статусы:** ⬜ не начата · 🟨 в работе · ✅ готова · ⛔ заблокирована решением заказчика

**Оценки** — человеко-дни для одного разработчика в паре с Claude. Не календарные сроки.

**Правило фазы:** фаза не считается закрытой, пока не выполнен её Definition of Done целиком. Задачи следующей фазы не начинаем — кроме явно помеченных `[можно параллельно]`.

# ФАЗА 1 — ДЕТЕРМИНИРОВАННОЕ ЯДРО

**Цель:** математический фундамент, который бит-в-бит одинаков в V8 и JavaScriptCore.
**Выход:** `packages/sim` умеет крутить пустой мир 5000 тиков с идентичным хешем на двух движках.

### 1.1 Примитивы

| ID | Задача | Ключевые детали | Тесты | Зависит | Оц. |
|---|---|---|---|---|---|
| **SIM-01** ⬜ | Fixed-point Q16.16 | Свободные функции над сырыми `int32`, **без классов и обёрток** (замер: обёртка = 24 нс/оп). `fxMul` через hi/lo split четырьмя `Math.imul`. `fxDiv` через double-деление + `\|0` — IEEE корректно округлено, значит бит-идентично во всех движках | Golden-векторы против **libfixmath** (MIT). Property-тест: `fxMul(a,1.0)===a`, `fxMul(-1,65536)===-1`, коммутативность | P0-07 | 3 |
| **SIM-02** ⬜ | Два числовых домена | Q16.16 для скоростей/нормалей/множителей (диапазон только **−32768…32767.99998**); **Q24.8 или Q32.0 для мировых координат** | Тест переполнения: `dx*dx+dy*dy` на координатах в тысячах не должен молча переполниться. Dev-сборка: runtime-assert через `Number.isSafeInteger` до `\|0` | SIM-01 | 1 |
| **SIM-03** ⬜ | PCG32 (XSH-RR) | Своя реализация ~40 строк, hi/lo 64-битное состояние через `Math.imul`. Константы `6364136223846793005` / `1442695040888963407`. Обязательны `getState()`/`setState()` | Golden-векторы из `rand_pcg` (Rust). Тест сериализации: сохранить → 100 вызовов → восстановить → те же 100 значений | SIM-01 | 2 |
| **SIM-04** ⬜ | Разделение RNG-потоков | Отдельные `inc` для: боевого потока, критов, косметики | Тест: 10000 косметических вызовов **не сдвигают** боевой поток ни на бит | SIM-03 | 0.5 |
| **SIM-05** ⬜ | Углы как BAM + таблицы | Угол = `uint32`, полный оборот = 2³² → модуль бесплатен, range reduction точен. Четвертьволновая таблица sin на **1024 записи `Int32Array` (4 КБ)** + линейная интерполяция → ошибка **~0.02 LSB Q16.16** | Сверка всех 4096 точек полного оборота с эталоном. `atan2` — против libfixmath | SIM-01 | 2 |
| **SIM-06** ⬜ | Избежание sqrt | Сравнение целей и дальностей — **по квадратам расстояний**. sqrt только для нормализации: LUT `1/sqrt` + одна итерация Ньютона | Тест: выбор цели даёт тот же результат, что и через точный sqrt, на 10⁶ случайных пар | SIM-05 | 1 |

### 1.2 Структуры данных

| ID | Задача | Ключевые детали | Тесты | Зависит | Оц. |
|---|---|---|---|---|---|
| **SIM-07** ⬜ | Свой SoA-слой (~200 строк) | `Int32Array` на компонент, sparse↔dense маппинг id↔index, битовые маски. **bitECS не берём:** внешняя зависимость + MPL-2.0 + порядок итерации `query()` не специфицирован | Бенч против массива объектов. **Ключевая метрика — p99, не среднее:** у SoA p99 ≈ avg, у объектов спайки ×2–3 из-за GC | SIM-02 | 3 |
| **SIM-08** ⬜ | Spatial hash на counting-sort бакетах | Два прохода за тик: (1) по возрастанию entityId считаем `counts[cell]`, (2) префиксные суммы → `cellStart`, (3) снова по возрастанию пишем в `dense`. Внутри ячейки id **строго по возрастанию** — порядок не зависит от истории вставок | Тест: результат идентичен при любом порядке добавления сущностей. Бенч: 840 юнитов, скан 3×3 | SIM-07 | 3 |
| **SIM-09** ⬜ | Ноль аллокаций в горячем цикле | Все буферы преаллоцированы, никаких `Set`/`Map`/генераторов | Тест: 1000 тиков без роста heap. **Генераторы с `yield` имеют «surprisingly high performance overhead»** — запрещены линтером | SIM-08 | 1 |

Обмен — **transferable `ArrayBuffer`** (константное время) либо SAB. ⚠️ `postMessage` со structured clone: безопасный потолок ~10 KiB на кадр, наш снапшот ~27 КБ — через clone **не пройдёт** | Тест: перенос в worker не изменил ни одного хеша | 3 |
| **APP-02** ⬜ | Решение по SharedArrayBuffer | SAB требует COOP/COEP → cross-origin isolation ломает сторонние встраивания. Альтернатива — transferable с двойной буферизацией (цена: +1 кадр задержки) | ADR в `DECISIONS.md` | 1 |

**Definition of Done фазы 3:**
- ✅ **60 fps на живом iPhone SE 2020**, 840 юнитов, замер в Safari, а не в эмуляторе
- ✅ ≤ 10 draw calls на кадр
- ✅ Тест «5 секунд»: 5 человек, не участвовавших в разработке, объясняют причину поражения по экрану результата
- ✅ Скип и ×4 работают, мгновенный результат по умолчанию
- ✅ Рендер физически не может повлиять на симуляцию (проверено тестом)

| ID | Задача | Ключевые детали | Оц. |

> **META-21 — единственное, что монетизирует наше требование детерминизма.** Академический разбор клиентских защит однозначен: любая клиентская защита обходится и лишь повышает стоимость атаки. Server-side replay verification — единственная настоящая защита, и она получается **бесплатно** из уже написанного детерминированного ядра.

```
P0-02 (решения) → P0-03 (каркас) → P0-07 (бенч fixed-point) ← ГЕЙТ
        ↓
SIM-01 (fixed-point) → SIM-07 (SoA) → SIM-08 (spatial hash) → SIM-17 (кросс-движок) ← ГЕЙТ
        ↓

        ↓
APP-10 (экран формации) → META-01 (сейв) → замкнутая петля
```

## Что в реестр НЕ вошло — и почему

| Отклонено | Причина |
|---|---|
| Ручные скиллы во время боя | Столп 1: «Никаких активируемых скиллов и ручного таргетинга». В оригинал Morale Skills добавили патчем 2015 — **это была правка, а не замысел**. Если нужны — Q-05 |

| Скрытая матрица контров 8×8 | Столп 2; прямая причина «each battle seemed the same» |
| Необъявленные шансы гачи | Столп 4 запрещает буквально |
| 4+ валют | Столп 4; Battle Legion как антипример |
