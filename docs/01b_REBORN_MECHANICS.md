## 1. Формула урона — и она не такая, как мы предполагали

Дословно с вики:

> The damage reduction is calculated using the following formula:
> **ATK × ATK / (ATK + enemy physical defence)**

Проверка по их же примерам:
- DEF = ATK → `ATK²/2ATK = ATK/2` → снижение 50% ✓
- DEF = 2×ATK → `ATK²/3ATK = ATK/3` → снижение 67% ✓
- DEF = 10×ATK → `ATK²/11ATK = ATK/11` → снижение 91% ✓

**Это процентная модель, но с одним принципиальным отличием от нашей.** У нас `ATK × K/(K+DEF)`, где `K = 400 + 15×level` — константа, которую надо подбирать под каждый диапазон уровней. У них роль K играет **сам ATK атакующего**.

Следствие огромное: **модель самонормируется**. Не нужно ни K, ни его подгонки под уровень 200. Когда растут и атака, и защита, соотношение сохраняется автоматически. Это снимает целый класс балансных проблем, с которым мы бы возились всю прогрессию.

**Магия считается отдельно и симметрично:** `MATK × MATK / (MATK + enemy MDEF)`. То есть два независимых канала урона и две независимые защиты. У нас сейчас один.

**Крит применяется после защиты:** `damage × (1 + crit multiplier)`. Совпадает с тем, что мы уже выяснили по оригиналу и заложили.

## 2. Вся система построена на одной формуле X/(X+Y)

Это, пожалуй, главная дизайнерская находка. Каждая пара противоборствующих статов считается одинаково:

| Что | Формула | При равенстве |
|---|---|---|
| Снижение урона | `ATK/(ATK+DEF)` | 50% |
| Шанс попадания | `Accuracy/(Accuracy+Dodge)` | 50% |
| Шанс крита | `CritChance/(CritChance+Tenacity)` | 50% |

Один и тот же закон убывающей отдачи везде. Игроку не нужно учить три разные механики — достаточно понять одну. Ни один стат не даёт неуязвимости: 91% снижения требует десятикратного превосходства.

**Это стоит взять целиком.** У нас сейчас крит — плоские 10%, уклонение отсутствует как стат. Единая формула даст и читаемость (столп 2), и защиту от вырожденных билдов.

**Скорость атаки:** интервал = `100 / attackSpeed` секунд. При 100 — удар в секунду, при 150 — каждые 0.6 с, при 50 — раз в 2 с.

**Скиллы не уклоняемы.** Уклонение работает только против обычных атак. Это делает скиллы надёжным источником урона против уворотливых целей и разводит два канала.

## 3. Таргетинг задан для каждого класса отдельно

Вот чего нам не хватало сильнее всего. У нас единый взвешенный score для всех. У них — **своя логика поиска цели у каждого класса**:

| Класс | Логика |
|---|---|
| **Sword Man** | ближайший в своём ряду; в ближнем бою **приоритет копейщикам** |
| **Shield Guard** | ближайший в своём ряду, затем просто ближайший |
| **Spearman** | ближайший в ряду; в ближнем бою **приоритет кавалерии** |
| **Cavalry** | ближайший в ряду; **если в ряду никого — самый ДАЛЬНИЙ в другом ряду**; приоритет лучникам |
| **Archer** | просто ближайший, без привязки к ряду |
| **Pegasus Knight** | ближайший маг или жрец в ряду; если нет — **ищет их в задних рядах** |
| **Magic Apprentice** | ближайший; в ближнем бою приоритет щитоносцам |
| **Novice Priest** | лечит щитоносца перед собой; если его нет — самого переднего союзника; дальше — самого раненого |

**Это и есть настоящий механизм контров.** Копейщик не просто наносит кавалерии +30% — он её *ищет*. Пегас не просто эффективен против магов — он *летит именно в них*, в том числе в задние ряды. Кавалерия при пустом ряду выбирает **самую дальнюю** цель, то есть намеренно ныряет в тыл.

Множитель без такого таргетинга — это лотерея: контр срабатывает, только если юниты случайно встретились. С таргетингом контр становится обещанием, которое игрок может закладывать в расстановку.

И для нашей проблемы Ланчестера это тоже важно: приоритеты **распыляют** урон по разным целям вместо фокуса на ближайшей, что само по себе ослабляет петлю обратной связи.

## 4. Матрица контров, точные числа

| Атакующий → Цель | Модификатор |
|---|---|
| Sword Man → Spearman | +20% |
| Spearman → Cavalry | +40% |
| Cavalry → Archer | +30% |
| Cavalry → Spearman | **−20%** |
| Archer → Pegasus | **+120%** |
| Archer → Mage | −15% |
| Pegasus → Magic | +30% |
| Pegasus → Priest | +30% |
| Magic → Shield Guard | +20% |

Свойства, которые стоит унаследовать: матрица **разрежена** (большинство клеток пусты), **асимметрична** (есть штрафы), и в ней ровно **один экстремум** — Archer против Pegasus на +120% при остальных 20–40%.

Один жёсткий контр среди мягких читается игроком несравнимо лучше, чем восемь средних. У нас сейчас плотная матрица 8×8 в диапазоне 0.6–1.6 — почти каждая пара что-то значит, а значит не значит ничего.

## 5. Прогрессия: три легиона вместо одной формации

**111 уровней престижа.** И ключевое — **три отдельные формации** («легиона»), каждая растёт независимо:

| | Открывается | Размер |
|---|---|---|
| Легион 1 | с начала | 6 → 30 слотов |
| Легион 2 | PL 40 | 6 → 30 |
| Легион 3 | PL 76 | 6 → 30 |

Это не пресеты одной армии, а три армии, которые нужны одновременно — под разные режимы и под многоэтапные бои. Ростер должен вырасти втрое, и решение «кого куда» становится втрое сложнее.

**Расписание открытия функций** — готовая кривая онбординга, выстраданная живой игрой:

| PL | Что открывается |
|---|---|
| 10 | чат |
| 17 | приключение, башня Мерлина |
| 27 | сундуки |
| 28 | **арена, магазин** |
| 34 | Phantom PvP |
| 37 | подземелья, **экипировка героев** |
| 40 | второй легион |
| 41 | большая арена |
| 48 | дерево юнитов, тренировочный полигон |
| 56 | система реликвий |
| 61 | дерево классов |
| 63 | резонанс, дуэли альянсов |
| 65 | заклинания, башня континента |
| 70 | мировой босс |
| 76 | третий легион |

Обрати внимание: **экипировка появляется только на 37-м уровне**, дерево классов — на 61-м. Игрок первые часы играет голым составом и одной механикой. Это прямая противоположность тому, чтобы вывалить всё сразу — и это то, на чём провалился Warcraft Rumble.

Энергия за уровень: 5 на старте, 8 к сотне. Растёт медленно.

| Класс | Героев |

По тирам: S — 2, S− — 2, A+ — 4, A — 2, A− — 7, B+ — 8, B — 6, B− — 6, C — 7, D — 4.

**Пирамида, а не лестница.** Основная масса в B и C, вершина узкая: два героя тира S на 48. Это здоровая структура — большинство героев играбельны, но не равны.

⚠️ Дисбаланс по классам заметен: жрецов трое против восьми кавалеристов. При этом жрец — единственный источник лечения. Похоже, саппорт намеренно держат дефицитным.

## 8. Экипировка: гайд честнее, чем вики

Из руководства сообщества, дословно:

> **The only equipment that matters are shadow weapons and legendary accessories. DO NOT UPGRADE ANYTHING ELSE!!**

То есть из всей системы экипировки реально работают два слота, остальное — балласт. Это провал дизайна, а не совет.

Приоритетные статы: скорость атаки, шанс крита, множитель крита, точность, уклонение, стойкость. Причём **скорость атаки почти для всех классов на первом месте** — потому что множество скиллов срабатывают «через N атак», и скорость атаки разгоняет не только урон, но и частоту скиллов.

По классам: щитоносцы и кавалерия «не получают особой пользы от экипировки», лучники получают больше всех.

**Урок для нас.** Если пять слотов экипировки из шести не решают, а два класса из восьми вообще не выигрывают от системы — значит система есть, а выбора нет. Наш `02_GDD` §4.1 закладывает шесть слотов; стоит проверить симулятором, что каждый на что-то влияет, прежде чем рисовать под них интерфейс.

## 9. Что берём в проект

| Находка | Решение |
|---|---|
| `ATK²/(ATK+DEF)` вместо `K/(K+DEF)` | **берём** — снимает подгонку K по уровням |
| Единая формула X/(X+Y) для всех пар статов | **берём** — одна механика вместо трёх |
| Раздельные физический и магический каналы | **обсудить** — удваивает число статов |
| Таргетинг с классовыми приоритетами | **берём** — это и есть механизм контров |
| Разрежённая матрица с одним экстремумом | **берём** — вместо плотной 8×8 |
| Скиллы не уклоняемы | **берём** |
| Интервал атаки = 100/скорость | **берём** |
| Три легиона | **не в v1** — умножает контент втрое |
| Экипировка, где решают 2 слота из 6 | **не повторять** — проверить симулятором |
| Общественное достояние вместо выдуманных имён | **берём** — законно и решает Q-09 |

Приоритетная связка — **таргетинг с приоритетами плюс разрежённая матрица**. Вместе они, скорее всего, ослабят и петлю Ланчестера из `BALANCE_01.md`: приоритеты распыляют урон, а разрежённая матрица убирает накопление множителей в каждой паре.
