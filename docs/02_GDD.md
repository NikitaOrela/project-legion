# 02 · Game Design Document

**Рабочее название:** `PROJECT_LEGION` (финальное имя — не «Mini Warriors», см. `00_START_HERE` §3)
**Жанр:** тактический авто-баттлер / формейшн-стратегия
**Платформы:** Web → iOS/Android (см. `03_TECH`)
**Референс:** Mini Warriors (Triniti, 2013), реконструкция в `01_RESEARCH`

---

## 1. Дизайн-столпы

Четыре принципа. Любая фича, которая им противоречит, отклоняется.

1. **Формация — это геймплей.** Игрок не управляет боем. Единственный рычаг —
   подготовка. Бой — это выполнение написанной игроком программы.
2. **Бой читаем.** После поражения игрок обязан понять причину за 5 секунд.
   Если не понимает — это баг дизайна, а не «сложность».
3. **Игра не умирает.** Кампания, прогресс и бой работают офлайн навсегда.
4. **Экономика не врёт.** Объявленные шансы = реальные шансы. Показатель силы
   либо честный, либо отсутствует.

## 2. Петля

### Микро-петля (30–90 секунд)
```
выбрать бой → расставить формацию → запустить → смотреть → результат → лут
```

### Макро-петля (сессия 10–20 минут)
```
дейлики → 5–10 боёв кампании → распределить лут →
прокачать 1–2 героя → пересобрать формацию → PvP-заход
```

### Мета-петля (недели)
```
открыть регион → выбить нового 4★ героя → перестроить архетип армии →
упереться в стену → сменить стратегию прокачки (уровни → скиллы)
```

## 3. Боевая система

### 3.1 Классы (стартовый набор — 8)

| Класс | Дальность | Скорость | HP | ATK | Роль |
|---|---|---|---|---|---|
| **Infantry** — пехота | 1 (ближний) | средняя | средняя | средний | универсал, наполнитель |
| **Pikeman** — пикинёр | 2 (короткий) | низкая | средняя | высокий vs конница | анти-кавалерия |
| **Paviser** — павиза | 1 | очень низкая | очень высокая | низкий | блокировщик, стена |
| **Cavalry** — кавалерия | 1 | очень высокая | высокая | высокий | прорыв, фланг, ассасин магов |
| **Archer** — лучник | 6 | средняя | низкая | средний | дальний DPS |
| **Arbalist** — арбалетчик | 8 | низкая | низкая | высокий, медленный | дальний бурст |
| **Mage** — маг | 5 | низкая | очень низкая | AoE | выжигание скучек |
| **Healer** — лекарь | 4 | средняя | низкая | лечение | поддержка |

Расширение контентом: Mounted Archer, Musketeer, Hammerman, Axeman, Griffin,
Savage-варианты. Это **модификаторы базовых классов**, не новые системы.

### 3.3 Сетка деплоя

```
        ТЫЛ
  ┌───┬───┬───┬───┬───┐
4 │   │   │   │   │   │   ← кавалерия
  ├───┼───┼───┼───┼───┤
3 │   │   │   │   │   │   ← дальние, хилы
  ├───┼───┼───┼───┼───┤
2 │   │   │   │   │   │   ← ближний DPS
  ├───┼───┼───┼───┼───┤
1 │   │   │   │   │   │   ← танки, павизы
  └───┴───┴───┴───┴───┘
        ФРОНТ
```

- 4 ряда × 5 колонок = 20 слотов, потолок
- Открыто на старте: 6 слотов (ряды 1–2, колонки 2–4)
- Открытие слотов по престижу (таблица `01_RESEARCH` §3.3)
- Каждый занятый слот = 1 герой + N миньонов его класса (N = размер отряда, 10→20)
- 3 сохранённых пресета

**Стартовая позиция юнита:** герой в центре ячейки, миньоны — сеткой позади
и по бокам от героя, компактным строем. Ряд 1 — на 15 % ближе к центру карты, ряд 4 — дальше.

### 3.4 Ход боя

| Фаза | Что происходит |
|---|---|
| **Setup** (t=0) | Обе армии спавнятся в своих зонах, застыв |
| **Advance** (t=0…) | Все юниты идут вперёд, скорость = MOVSPD класса |
| **Engage** | При входе цели в радиус — остановка и атака |
| **Melee** | Разрешение столкновений, блокировка павизами |
| **Resolve** | Смерть героя → его выжившие миньоны получают −40 % ATK/DEF («moraleBreak») |
| **End** | Все герои одной стороны мертвы, ИЛИ t = 180 с |

При таймауте побеждает сторона с бо́льшим `Σ(HP_current) / Σ(HP_max)`.

### 3.5 Таргетинг

Каждый юнит раз в `RETARGET_INTERVAL` (0.5 с) выбирает цель:

```
score(target) = W_dist × (1 / (1 + distance))
              + W_affinity × (сlass(target) == class(self) ? 1 : 0)
              + W_counter × C[self.class][target.class]
              + W_hero    × (target.isHero ? 1 : 0)
              + W_lowhp   × (1 - target.hp / target.hpMax)
```

Стартовые веса: `W_dist=1.0, W_affinity=0.6, W_counter=0.4, W_hero=0.15, W_lowhp=0.2`

`W_affinity` — та самая наблюдённая аффинность («кавалерия идёт на кавалерию»).
Она даёт узнаваемый рисунок боя и делает результат предсказуемым для игрока.

Специализации:
- **Cavalry**: `W_dist` понижен до 0.3 → игнорируют ближних, летят вглубь
- **Mage**: цель = центр наибольшей скученности врагов (grid density scan), не ближайший
- **Healer**: цель = свой союзник с минимальным `hp/hpMax` в радиусе

### 3.6 Блокировка (Paviser)

Реализация механики-стены:

```
если unit.isMelee И существует враг-Paviser в радиусе BLOCK_RADIUS (= 1.2 × attackRange):
    unit.blockedBy = paviser
    unit.canAdvance = false
    unit.target = paviser
    пока paviser жив ИЛИ unit не выбьется (5 с таймаут «переагра»)
```

Стоимость: павиза жертвует уроном ради удержания. Награда: заблокированные
враги — статичные мишени для дальних и магов.

### 3.7 Формула урона

```
raw       = ATK × C[attackerClass][defenderClass]
mitigated = raw × (K / (K + DEF))            где K = 400 + 15 × level
crit      = roll(critChance) ? critMultiplier : 1.0
variance  = 0.95 + rng() × 0.10
damage    = max(1, floor(mitigated × crit × variance))
```

**Калибровка по наблюдению из `01_RESEARCH` §5.2:**
ATK 2191 + крит → ~900 итогового урона. Значит `mitigated × crit ≈ 900` при
`crit ≈ 1.5`, откуда `mitigated ≈ 600`, `K/(K+DEF) ≈ 0.27` → при `K ≈ 1150`
(level 50) получаем `DEF ≈ 3100`. Реалистично.

> **Следствие, которое надо сохранить:** обычные атаки — фон. Основной урон
> идёт от скиллов. Это делает HP/DEF главными статами и превращает выживаемость
> в источник урона. Это неочевидно и это хорошо.

### 3.8 Скиллы героев

Каждый герой: 1 пассивка + 1 активный скилл с шансом прока.

**Прок:** проверка при каждой нормальной атаке героя. При успехе — скилл вместо атаки.

**⭐ Инвариант баланса (главное правило системы):**

```
procChance × skillDamage = SKILL_BUDGET(stars, skillLevel)

SKILL_BUDGET(stars, lvl) = BASE[stars] × (1 + 0.05 × lvl)

BASE = { 1★: 120, 2★: 200, 3★: 300, 4★: 400, 5★: 520 }
```

Дизайнер задаёт **только `procChance`** (30 / 40 / 50 / 60 %), урон вычисляется:
`skillDamage = SKILL_BUDGET / procChance`.

Результат: все герои одной редкости равны по ожидаемому урону, различаются
**дисперсией**. 30 %/большой удар = свинговый герой, 60 %/маленький = стабильный.
Это даёт «фил разницы» без мета-доминанты.

*(+5 % за уровень скилла — прямая цифра из оригинала, `01_RESEARCH` §5.4.)*

**Архетипы скиллов:**

| Тип | Действие | Классы |
|---|---|---|
| AoE Burst | урон в круге R вокруг цели | Mage, Axeman, Hammerman |
| Line Strike | урон по линии | Cavalry, Whirler |
| Global Hero Nuke | урон всем героям врага (дорогой, только 4★+) | Mounted Archer |
| Multi-shot | N ударов по случайным целям | Archer, Arbalist |
| Team Buff | +X % ATK/DEF союзникам на T сек | Support |
| Mass Heal | лечение всем в радиусе | Healer |
| Shield | поглощение урона | Paviser |
| Reflect | возврат % урона | Reflector Paviser |

### 3.9 Мораль

При смерти героя его отряд получает `moraleBreak`: −40 % ATK, −40 % DEF, −20 % MOVSPD.
Это делает героев приоритетной целью и создаёт каскадные развалы фронта —
драматургия боя без скриптов.

## 4. Прогрессия

### 4.1 Оси прокачки (все пять — обязательны)

| Ось | Ресурс | Что даёт | Потолок |
|---|---|---|---|
| **Престиж** (аккаунт) | опыт с боёв | слоты деплоя, размер ростера, доступ к контенту | 80+ |
| **Уровень героя** | золото | HP, ATK, DEF | = престиж (кап) |
| **Уровень скилла** | свитки | +5 % к силе скилла за уровень | 12 |
| **Звёзды героя** | дубликаты из гачи | база статов, потолок скилла | 5★ |
| **Снаряжение** | дроп + кузница | статы по 5 слотам | фиолет+ |
| **Уровень/размер отряда** | золото + материалы | HP/ATK миньонов, N миньонов | 20 |

Пять осей — это намеренно. Игрок всегда имеет несколько вариантов, куда вложить,
и каждый ресурс тратится в своё место. Стены прогресса на разных осях не совпадают.

### 4.2 Кривые (стартовые формулы для калибровки)

```
prestigeXP(n)     = 100 × n^1.7
heroLevelCost(n)  = 50 × n^2.1                          (золото)
heroStatAtLevel   = base × (1 + 0.08 × (level - 1))
skillLevelCost(n) = 5 × n^1.8                           (свитки)
squadSizeCost(n)  = см. таблицу 01_RESEARCH §3.4        (прямой перенос)
```

**Правило кап-лока:** `heroLevel ≤ prestigeLevel`. Не даёт закачать одного
героя в потолок и снести кампанию — заставляет расти вширь.

### 4.3 Асимметрия ростера и деплоя

Прямой перенос из оригинала (`01_RESEARCH` §3.2–3.3):

```
maxRoster = 11 + floor((prestige - 1) / 4)
maxDeploy = 6  + floor(prestige / 5)          (с замедлением после 60)
```

Ростер всегда больше деплоя → **постоянное решение о составе**. Это критично.

## 5. Экономика

### 5.1 Валюты

| Валюта | Тип | Кран | Слив |
|---|---|---|---|
| Золото | soft | бои, квесты, дейлики | уровни героев и миньонов, размер отряда |
| Кристаллы | hard | IAP, ачивки, дейлики, PvP-сезон | рефреш гачи, энергия, сундуки |
| Свитки | специальный | элитные стадии, рейды | уровни скиллов |
| Осколки героя | специальный | гача-дубли, магазин | звёзды героя |
| Материалы отряда | специальный | бои | размер отряда |
| Энергия | таймер | +1 / 5 мин (288/сутки), кристаллы | вход в наградной бой |

### 5.2 Энергия — с исправлением главной ошибки оригинала

Прямой перенос цифр: **288/сутки, обычный бой 6, элитный 8**
(48 или 36 боёв в сутки соответственно).

**Но:** в оригинале лимит боёв был главной претензией прессы (Arcade Sushi, 2013).
Наше исправление:

> **Энергия гейтит только награды, не игру.**
> Свободный режим («Спарринг») — неограниченные бои против любой формации,
> включая свои сохранённые пресеты и формации из PvP-лога. Без лута.
> Игрок может тестировать гипотезы сколько угодно — это и есть настоящий геймплей.

Это сохраняет монетизационный крючок и убирает главный источник негатива.

### 5.3 Два крана лута

| Режим | Стоимость | Выход |
|---|---|---|
| **Обычная стадия** | 6 энергии | опыт (полный), золото (×0.5 при дропе), снаряжение |
| **Элитная стадия** | 8 энергии | опыт (меньше), золото (полное), **свитки**, осколки |

Точка смены стратегии ≈ престиж 50: до неё выгоднее обычные (набор уровня),
после — микс (свитки решают, см. `01_RESEARCH` §5.5). Эта развилка —
намеренный дизайн, а не побочный эффект.

### 5.4 Гача — честная

| Правило | Значение |
|---|---|
| Шансы | Опубликованы в UI на экране призыва, всегда, не в подменю |
| Pity | Гарантированный 4★ за 60 роллов, счётчик виден игроку |
| Soft pity | С 45-го ролла шанс 4★ растёт линейно |
| Дубликаты | Конвертируются в осколки → звёзды. Дубль никогда не «в никуда» |
| Обещания | Если UI говорит «гарантированно» — это правда. Без исключений |

Стартовые шансы: 4★ — 2 %, 3★ — 12 %, 2★ — 35 %, 1★ — 51 %.

### 5.5 Монетизация

Никакого прямого pay-to-win. Продаём **время и косметику**:

| Продукт | Что даёт |
|---|---|
| Восстановление энергии | ускорение фарма, не сила |
| Боевой пропуск (сезон) | косметика + бонус-ресурсы по прогрессу игры |
| Скины героев и знамёна | чистая косметика |
| Стартовые наборы | ускорение раннего онбординга |
| Отключение рекламы | если реклама вообще будет |

Гача продаёт **роллы**, но потолок силы достижим F2P за разумное время.
Целевая конверсия: 2–4 % платящих, ARPPU $15–25.

## 7. UX-требования

### 7.1 Читаемость боя (столп №2)

Обязательные элементы:
- **Полоски HP героев** сверху экрана, обе стороны, всегда видны
- **Всплывающий урон** дифференцирован цветом: обычный / крит / скилл / контр
- **Индикатор контра** — краткая иконка «↑» при срабатывании множителя > 1.2
- **Скорость 1× / 2× / 4×** и мгновенный автобой (пропуск с результатом)
- **Пост-бой отчёт** обязателен: топ-3 по урону, топ-3 по полученному урону,
  где сломалась линия, сколько раз прокнули скиллы, кто кого контрил

> Правило: игрок должен ответить на вопрос «почему я проиграл» за 5 секунд
> после экрана поражения, не переигрывая.

### 7.2 Формация

- Drag & drop героя на слот
- **Превью-подсказка**: подсветка ожидаемых контров против формации противника
  (для кампании — известна заранее, для PvP — по последнему логу)
- 3 пресета с именами
- Кнопка «Авто» — заполнение по эвристике, для казуалов; никогда не оптимальна

### 7.3 Показатель силы

Либо честный `POWER = Σ(HP + ATK×k1 + DEF×k2 + SKILL_BUDGET×k3)` с явным весом
скиллов, либо не показываем вовсе. Ошибку оригинала (AP без учёта скиллов)
не повторяем.

## 8. Арт-дирекшн

- Чиби-пропорции: голова ~1/3 высоты, читаемый силуэт при высоте 32–48 px
- **Силуэт решает всё**: на экране 800 юнитов, класс должен читаться по силуэту
  и цвету за 0.2 с. Тест: обесцветить спрайт и уменьшить до 24 px — класс всё ещё узнаваем?
- Палитра: своя сторона — холодная, враг — тёплая. Одинаковая для всех классов
  внутри стороны, различие — форма
- Анимации: idle / walk / attack / skill / death, 4–8 кадров каждая
- Формат: спрайт-атласы, единый pivot, power-of-two текстуры
- Инструменты: Aseprite (пиксель) или Spine/DragonBones (скелетка)

**Экономия:** миньоны одного класса = один спрайт-сет + цветовая перекраска
через шейдер. Герой = тот же сет + отличительный элемент (плащ, шлем, оружие).
80 героев ≠ 80 анимаций, а 12 базовых сетов + вариации.

## 9. Что НЕ входит в скоуп (защита от расползания)

Отклонено на этапе спеки. Пересмотр — только после релиза:

- ❌ Ручное управление в бою (нарушает столп №1)
- ❌ Активация скиллов игроком
- ❌ 3D
